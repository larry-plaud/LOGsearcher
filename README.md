# LOG周期分析（LOGsearcher）

> 一款 Windows 桌面工具，用于解析 UART 串口 LOG 文件，按标志位自动切分测试**周期**，判定每个周期为 **成功 / 误码 / LOG丢失**，并支持筛选查看与导出 Excel。

## 功能特性

- 📂 **一键导入** `.txt` / `.log` 文本 LOG 文件。
- ⚙️ **自动切分周期**：以 `console_uart_write`、`uart_rx_dma_enable` 两个标志位为界，将 LOG 划分为一个个测试周期。
- 🧮 **状态判定**：每个周期自动判定为 **成功**、**误码** 或 **LOG丢失** 三种状态之一。
- 📊 **统计概览**：顶部卡片实时显示 成功 / 误码 / LOG丢失 / 总周期数。
- 🔍 **状态筛选**：按全部 / 成功 / 误码 / LOG丢失 快速过滤明细表。
- 📋 **周期明细**：表格列出每个周期的序号、起止时间戳、起止标志位、Missing 次数与状态。
- 💾 **导出 XLSX**：一键导出多工作表 Excel（统计汇总 + 全部周期 + 各状态分表），并可选择导出后立即打开。
- ⚡ **异步解析**：解析在后台线程执行，界面不卡顿，并显示耗时。
- 🌙 **深色界面**：护眼的深色主题，适合长时间查看日志。

## 使用说明

1. 点击 **📂 选择文件**，选择要分析的 `.txt` / `.log` 文件。
2. 点击 **▶ 开始分析**，程序在后台完成解析，顶部统计卡片与明细表随即更新。
3. 使用 **筛选状态** 按钮（全部 / 成功 / 误码 / LOG丢失）过滤明细表；筛选计数会显示为 `显示 XXX: N / 总数`。
4. 需要留存结果时，点击 **💾 导出 XLSX**，选择保存路径即可生成 Excel 报表；导出完成后可选择立即打开。
5. **系统日志** 区域会记录每一步操作、解析统计明细以及耗时，便于排查。

## LOG 格式与识别规则

程序按行扫描文本，通过**关键字**识别三类事件标志位：

| 简写 | 关键字（子串匹配）              | 含义                      |
|------|-------------------------------|--------------------------|
| C    | `console_uart_write`          | 控制台 UART 写           |
| U    | `uart_rx_dma_enable`          | UART 接收 DMA 使能       |
| M    | `Maybe there are missing logs!` | 可能存在丢失的日志       |

> 识别为**子串包含**，不要求整行完全相等；同一行若同时包含 C 与 U，会各自记为一个事件。

### 时间戳提取

每个事件会尝试提取时间戳，支持两种格式（按优先级）：

1. **行首标准格式**：`<序号> MM-DD#HH:MM:SS.mmm <数字>`
   例如 `123   08-31#14:57:03.128   456`
2. **括号内格式**：`(MM-DD#HH:MM:SS.mmm)`
   例如 `... (08-31#14:57:03.128) ...`

若两种都未匹配，时间戳留空。

## 周期判定逻辑

程序从事件流中依次取出**起始标志位**与其后的**下一个标志位**作为**终止标志位**，并统计两者之间出现的 Missing(M) 次数，据此判定状态：

| 起始 → 终止 | Missing 数 | 判定状态   | 说明                          |
|-------------|-----------|-----------|-------------------------------|
| C → U       | 任意       | ✅ **成功**   | 一次完整的正常收发            |
| C → C       | 0         | ⚠️ **误码**   | 两次发送之间无接收，且无丢失提示 |
| C → C       | ≥ 1       | ❌ **LOG丢失**（CC 型） | 两次发送之间夹有丢失提示     |
| U → U       | 任意       | ❌ **LOG丢失**（UU 型） | 连续两次接收                  |
| U → C       | 任意       | —（跳过）  | 视为孤立的 U，跳过后重新起算   |

**游标推进规则**（决定下一个周期从哪里开始）：

- **成功（C→U）**：游标越过 U，U 被完整消费。
- **误码 / CC 丢失（C→C）**：游标停在第二个 C，即第二个 C 作为下一周期的起点。
- **UU 丢失（U→U）**：游标停在第二个 U，即第二个 U 作为下一周期的起点。

> `LOG丢失` 在统计上是一个整体，但内部会额外区分 **CC 型**（C→C 且有 Missing）与 **UU 型**（U→U）两种来源，仅用于日志中的信息展示。
> 若事件流在找到匹配的终止标志位前结束，则该未完成周期被静默丢弃，不计入结果。

## 导出的 Excel 结构

导出的 `.xlsx` 包含以下工作表（各状态分表仅在存在数据时生成）：

| 工作表     | 内容                                             |
|-----------|--------------------------------------------------|
| 统计汇总   | 成功 / 误码 / LOG丢失 / 总周期数 的数量汇总        |
| 全部周期   | 所有周期的完整明细                                 |
| 成功       | 仅成功状态的周期                                   |
| 误码       | 仅误码状态的周期                                   |
| LOG丢失    | 仅 LOG丢失状态的周期                               |

明细表列：**序号、起始时间戳、结束时间戳、起始标志位、终止标志位、Missing次数、状态**。
（时间戳列强制为文本格式，避免 Excel 自动转换。）

默认文件名格式为：`<原文件名>_周期分析_yyyyMMdd_HHmmss.xlsx`。

## 项目结构

```
LOGsearcher/
├── App.xaml / App.xaml.cs          # WPF 应用入口
├── MainWindow.xaml                 # 主界面布局与深色主题样式
├── MainWindow.xaml.cs              # 界面交互：选择文件、分析、筛选、导出
├── LogParser.cs                    # 核心解析与周期判定逻辑（纯逻辑，无 UI 依赖）
├── AssemblyInfo.cs                 # 程序集主题信息
├── LOGsearcher.csproj              # 项目文件（.NET 10 WPF）
├── LOGsearcher.slnx                # 解决方案文件
├── logsearch.ico                   # 应用图标
└── .github/workflows/release.yml   # 打 tag 自动构建并发布单文件 EXE
```

**核心模块说明：**

- `LogParser.cs`：不依赖任何 UI，负责文件扫描、事件识别、时间戳提取与周期判定，输出 `ParseResult`（含统计计数与 `CycleResult` 列表）。可独立测试与复用。
- `MainWindow.xaml.cs`：负责界面交互，通过 `Task.Run` 在后台调用 `LogParser.Parse`，并使用 [ClosedXML](https://github.com/ClosedXML/ClosedXML) 生成 Excel。

## 自动发布（CI）

仓库内置 GitHub Actions 工作流 `.github/workflows/release.yml`：

- **触发条件**：推送以 `v` 或 `V` 开头的 tag（如 `v1.0`），或在 Actions 页面手动触发。
- **构建产物**：`win-x64` 自包含、压缩的**单文件 EXE**，命名形如 `LOGsearcherV1.0.exe`（版本号取自 tag）。
- **发布**：tag 触发时自动创建 Release 并上传 EXE；手动触发时仅上传为 Artifact，不创建 Release。

发布新版本示例：

```bash
git tag v1.0
git push origin v1.0
```

## 常见问题

**Q：提示"请先选择有效的 LOG 文件"？**
A：请确认已通过"选择文件"选定一个真实存在的文件后再点击"开始分析"。

**Q：解析后周期数为 0？**
A：说明文件中未识别到 `console_uart_write` / `uart_rx_dma_enable` 标志位，请确认 LOG 内容与格式是否符合[识别规则](#log-格式与识别规则)。

**Q：导出时提示"暂无数据可导出"？**
A：需先成功分析一份 LOG 文件后才能导出。

**Q：EXE 能在没有安装 .NET 的电脑上运行吗？**
A：可以。Releases 中的 EXE 为自包含单文件，已内置运行时，直接双击运行即可。
